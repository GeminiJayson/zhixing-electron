# 原型：页面级工具栏（可抛弃）

> 这是**原型**，不是生产代码。判定标准是「变体之间**结构**不同」，不是换颜色。
> 选定一个变体后：把赢家落进各页真实代码，其余变体 + 切换栏 + 本目录一起删掉，
> 或整体挪到一次性分支 `prototype/toolbars`。

## 要回答的问题

**八个功能区的工具栏，应该长成同一套什么结构？**

审计现状 —— 同一个应用里出现了 6 种工具区写法，而且**搜索框、主操作、统计文本的位置每页都不一样**：

| 功能区 | 现在的工具区 | 位置漂移的问题 |
| --- | --- | --- |
| 今日 | `.quick-add`（输入 + 添加） | 只有主操作，没有导航/筛选 |
| 任务 | `.tasks-toolbar`：seg 视图 + 统计 + 右侧「清单下拉 / 新建清单 / 过滤输入 / 批量 / 速览 / 新建任务」 | 搜索框混在右侧操作组里；主操作在组末 |
| 收件箱 | `.seg` tab + `.flash-new` + `.flash-toolbar` | **一页三条工具条**，三种间距与控件组合 |
| 笔记 | 树内 `.ntree__tools`（搜索 + 格式 + 2 图标）、编辑区 `.rt-editor__bar` | 搜索框跑到侧栏里 |
| 工作流 | `.tasks-toolbar`：统计 + 右侧 **12 个控件** | 最拥挤，主操作「启动实例」被埋在中间 |
| 图谱 | `.tasks-toolbar`：seg + 2 下拉 + 搜索 + 统计 + 右侧 3 按钮 | 搜索框在这里**在左侧**（任务页在右侧）；没有主操作 |
| 设置 | `.seg` tab 栏 | 导航与标题分离 |
| 回顾 | 无工具区 | 纯展示，不需要 |

## 三条变体

同一批操作项，三种**结构**：

- **A 单行三段** —— `[标题] [导航] …… [搜索] [筛选] [⋯ 次要收进菜单] [主操作]`
  一屏一行，垂直空间最省。次要操作（批量 / 速览 / 新建清单 / 重新布局…）收进 `⋯`。
- **B 双层** —— 第一层 `[标题 + 副标题] …… [主操作]`；第二层 `[导航] [搜索] [筛选] …… [次要平铺]`
  主操作与标题同行，导航/筛选/搜索独占第二层。适合操作多的页面。
- **C 折叠命令式** —— 常驻只有 `[标题] …… [搜索] [视图与筛选 ▾] [主操作]`
  视图切换 / 筛选 / 次要操作全收进一个操作浮层，分组列出（视图 · 筛选 · 操作）。

三条变体都让工具条 **sticky 常驻**（现状是随内容滚走）—— 这是本原型要一并评估的点。

## 怎么跑、怎么切

```bash
npm run prototype:toolbars
```

- 底部会出现黑色切换栏：`← A (单行三段) →`，左右箭头或键盘 `←` `→` 循环切换。
- 变体记在 URL hash 里：`#ptoolbar=A` / `=B` / `=C`，可分享、刷新稳定。
- **不带 hash 时是 `off`**：渲染各页**原有**工具栏，普通用户永远看不到原型。按 `×` 也可退出。

## 覆盖范围

- 已接入：**今日 / 任务 / 收件箱 / 工作流 / 图谱 / 设置** 六个页面级工具区（含标题行）。
- 未接入（有意）：
  - **笔记树 `.ntree__tools`** 与 **编辑器格式条 `.rt-editor__bar`** —— 组件内工具区，语义不同（树操作 / 文本格式），
    不随页面级变体重排；它们的控件规格已在上一轮统一。
  - **回顾页** 无工具区；**桌面浮窗** 是独立小形态。
  - **收件箱的 `.flash-new` / `.flash-toolbar`** 未合并进变体 —— 它们正是「一页三条工具条」的证据。
    选定变体后再决定归宿（A 的 `⋯`？C 的操作浮层？）。
- 无写入路径改动：原型只重排已有按钮与输入，事件处理函数全部复用页面原有实现。

## 怎么判读

翻页看同一变体在各功能区的表现，重点看四个问题：

1. **主操作是否总能一眼找到**（A 在工具行末、B 在标题行、C 常驻）？
2. **搜索框位置是否一致**（现状任务页在右、图谱页在左）？
3. **导航（视图/范围/tab）是否和操作混在一起**？
4. **工具条常驻**是否值得多占那一条高度？

typical 反馈是「我要 B 的标题行 + A 的 ⋯ 收纳」，那就是最终设计。
