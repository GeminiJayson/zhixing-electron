## 知行 ZhiXing 1.7.0

本地优先的个人待办 + 知识图谱桌面端（Windows x64）。数据只存在本机的一只 SQLite 文件里：无需注册账号，不联网也能完整使用。

### 一、任务与提醒

- **完成的任务不再堆在当前清单里**：一旦完成（或放弃）就从当前清单收走，统一进「已完成」清单（清单筛选里多了一项）。清单里剩的都是真要做的事。子任务例外 —— 父任务还在，它就随父任务显示。四象限 / 日历 / 看板不受影响，日历仍由设置里的「日历显示已完成」控制。
- **提醒从悬浮表情旁边冒出来**：到点提醒不再只是主窗口右上角一张卡片。悬浮球旁边的气泡成为主要呈现，球同时切到提醒表情；气泡锚在球旁边并跟随移动，可「稍后 5 / 15 / 30 分」「查看」「知道了」。浮窗被关掉时提醒回落到主窗口卡片，不会因为关浮窗而丢失。
- **提醒时刻终于可以自己设了**：任务编辑面板新增「提醒」一行（日期 + 时刻）。此前提醒时刻只有一个来源 —— 快速捕获里写「明天3点」；任务建好之后就再也改不了。只选日期不选时刻时按 09:00 提醒。
- **到点提醒的卡片与删除确认、捕获面板这些弹框长得一样了**：同一个应用里原先有两套卡片外观（提醒是暖色描边 + 大圆角，弹框是主题描边 + 更大圆角），现在三个面（主窗口提醒卡、悬浮表情气泡、独立弹窗）复用同一套卡片样式，换主题时一起变。
- **修复：悬浮表情的提醒气泡此前不跟随主题。** 气泡跑在独立窗口里，没有应用当前主题，用的是兜底色 —— 主窗口是浅色、气泡却是深色。

### 二、一轮全库审计与修复

这一版在功能之外，做了一次覆盖全库（140 个源文件、约 3 万行）的设计缺陷审计，并修掉了其中全部严重级问题。下面几条是你能直接感觉到的：

- **修复：附件链接与图片原图预览在 Windows 上完全失效。** 1.6.0 的更新说明里写了「双击图片用原图预览」，这条实际不成立 —— 拼接 file 协议地址时没有处理 Windows 的反斜杠路径，得到的是非法地址。缩略图是内嵌数据所以看着正常，把这个问题掩盖了一整个版本。现在缩略图、原图预览、附件链接都正常了。
- **修复：「清单设置」会把「取消」变成「删除清单」。** 改名对话框的默认值就是当前名，改名分支不成立时（没改名，或点了取消）会继续往下走，弹出删除确认。现在改名与删除是两个独立入口。
- **修复：切走页面会丢掉最后一次编辑。** 在笔记里输入后 800 毫秒内切到别的页，这段编辑会静默丢失。现在切页时会先把待保存的内容落盘。
- **修复：备份策略会优先删掉自动备份。** 备份文件名形如 auto-时间戳.db 或 pre-restore-时间戳.db，而清理时按整个文件名排序 —— 字母序先按前缀分组，于是攒够 10 份后自动备份会被优先删除，留下的反而是某一刻手动动作的快照。现在按时间戳排序。
- **修复：智能清单与列表对同一条任务给出相反的结论。** 已放弃的任务在列表里显示为已完成，在未完成筛选里却被当成未完成。另外，无法识别的截止条件会让清单一条不剩且毫无提示，现在会明确告诉你哪一段没看懂。
- **修复：快速捕获的「下周X」算错。** 输入「下周五」会得到本周五，而且标题里会残留一个「下」字；「下下周五」则会被吃掉日期词却不设置日期。
- **修复：图谱会闪出并不存在的节点增删。** 在图上点一下节点，之后任何写入都会推一批错误的增量。
- **修复：笔记正文的 Markdown 预览右键会弹出两个重叠的菜单。**
- **修复：外部任务同步会覆盖你自己写的内容。** 按标题「认领」本地同名任务后，下一次同步会无条件用外部数据覆盖标题、备注、截止与优先级。现在认领来的任务只补空字段。
- **安全**：笔记预览的两套 HTML 清洗合并为一套严格白名单（原先 Markdown 预览走的是黑名单，可被 tab 混淆这类手法绕过）。

### 三、内部质量与验证

- **「多步写没有事务边界」统一收口**：一次操作要写多行或多表时，原先靠业务代码自己保证一致性，中途失败会留下半完成状态。现在一致性边界回到主进程，并新增六类批量入口（批量删除任务与标签、批量撤销、批量写节点坐标、清空回收站、批量存附件）。方案记录在 docs/adr/0001-多步写的事务收口.md。
- **12 道架构护栏**（src/shared/architecture.test.ts）：禁止渲染层循环调 IPC、多步写必须在事务内、提醒必须先派发后消费、订阅必须可取消、消毒只有一份、完成态判据只有一份、广播域表不许漂移、直接插入的任务必须建索引、图谱基线只由全图视图更新、右键菜单只有一个 owner、验证脚本不得污染真实库、验证脚本不依赖外部 CLI。每一道都对应一个真实发生过的回退风险。
- **修好了验证基础设施本身**：一批端到端脚本此前实际上跑不起来 —— 13 个脚本用了 macOS 的库路径（Windows 上直接抛错）、13 个脚本依赖未安装的 sqlite3 命令行、16 个脚本依赖一个已从工作区删除的备份库。三者叠加的效果是「脚本早早退出，断言从未执行」，而其中就包括「真实库未被写入」这道唯一能发现测试污染的关卡。顺带修掉一个真问题：截图脚本会把主题设置写进你的真实库。

### 兼容性

- 数据库仍是 schema v12，本版没有改动表结构（新增的应用私有列由初始化逻辑自动补齐）；与 Python 版继续共用同一只库文件，顺序打开即可，不要同时打开。
- 升级安装不会动你的数据；卸载也不会删除数据。
- 已有的任务与提醒数据无需迁移。
