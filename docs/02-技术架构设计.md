## 4. IPC 与「按域广播」

### 4.1 通道规模

| 来源 | 通道数 | 说明 |

### 4.2 写操作广播（O3）

核心设计：**广播写在 IPC 包装器里，而不是散落在每个 handler 中**（`src/main/db/index.ts:140-143` 注释）：



- `WRITE_DOMAINS`（`src/main/db/index.ts:49-120`）是**唯一**的「写通道 → 域」映射表，本轮实测 **69** 条；读通道不进表。
- 域枚举为 5 个：`'task' | 'note' | 'flash' | 'workflow' | 'settings'`（`src/shared/events.ts:9`）。
- 支持一次写操作声明多个域：图谱连线编辑动的是两端真数据，`db:connectGraphNodes` / `db:removeGraphEdge` / `db:rewireGraphEdge` 声明为 `['note','task']`（`:94-97`）。
- 广播实现遍历所有窗口（`BrowserWindow.getAllWindows()`），因此**桌面浮窗也能同步**；同时调用主进程侧钩子刷新托盘（`:128-138`）。
- 特例：`db:restoreBackup` 成功后**五个域全部广播**（`:272-279`），因为整库被替换。
- 已知缺口：`restoreTrash`/`purgeTrash`/`emptyTrash`/`purgeTrashOlderThan`/`import*` 目前统一映射为 `'task'`（`:105-119`），note/flash/settings 视图不会自动刷新（详见 `04` 文档 D14）。

### 4.3 渲染侧订阅

`src/renderer/src/App.tsx:136-140` 启动时调用一次 `bindHostEvents(window.zhixing.db)`（`src/shared/events.ts:39-43`），把主进程的 `data:changed` 接进订阅表；页面用 `subscribeDomain(['note','task'], cb)`（`src/shared/events.ts:24-29`）只订阅自己关心的域。

### 5.1 连接与事务约定

- 数据目录与 Python 版 `data_dir()` 逐条对齐，支持 `ZHIXING_HOME` 覆盖（`connection.ts:18-32`）——这既是便携模式，也让写入验证跑在副本库上。
- PRAGMA：`journal_mode = WAL`、`foreign_keys = ON`、`busy_timeout = 4000`（`connection.ts:141-143`）。
- 「零表才算全新库」：用一个 `sqlite_master` 计数判定，避免 0 字节文件让整个应用只会报 `no such table`（`connection.ts:144-152`）。
- 建库失败时只清理**自己刚创建**的文件（`creating && !existed`），绝不动用户已有库（`connection.ts:163-164`）。
- 时间戳必须写成 Python `datetime.now()` 的默认字符串形态（微秒 6 位），否则 SQLAlchemy 再读该列会解析失败（`connection.ts:178-190`）。
- 迁移前强制备份失败即中止（`connection.ts:102-104`），宁可打不开也不冒险改主库。
- 索引说明：生成的 `SCHEMA_SQL` 只含 21 张表 + 3 张 FTS5 虚拟表、**不含任何 `CREATE INDEX`**；唯一的业务索引来自 v12 迁移步骤（`src/main/db/migrate.ts:117`，Python 侧同点位 `zhixing/model/infrastructure/db.py:236`）。

### 6.2 跨仓库契约：`schema.ts` 是生成物

Electron 侧没有 ORM，库文件不存在时必须自己建库；而两版**共用同一个 SQLite 文件**，DDL 必须与 Python 的 `Base.metadata.create_all + _FTS_DDL` **逐字一致**——手抄必然漂移，所以由生成器固化。

| 环节 | 事实 | 证据 |
| --- | --- | --- |
| 生成器（Python 侧） | `export-schema.py`：建探针库 → `create_all` + `_FTS_DDL` → 读 `sqlite_master` → 改写为 `IF NOT EXISTS` → 写出 `schema.ts` | 当前工作区内位于 `scripts/export-schema.py:1-87`；`import` 声明与目标见 `:20-25` |
| 权威模型 | Python 侧 SQLAlchemy 模型 | `scripts/export-schema.py:22`：`from zhixing.model.infrastructure.models import Base, SCHEMA_VERSION` |

| 面 | 措施 | 证据 |
| --- | --- | --- |

## 12. 已知架构债与维护约定

1. **`docs/README.md` 与代码不一致（重要）**：`README.md:24` 仍写「以只读方式打开（`readonly: true`）」，而 `src/main/db/connection.ts:137-152` 是读写打开；`README.md:52-53` 把任务/笔记/图谱/收件箱/工作流/回顾/设置列为「待迁移」，实际 8 页均已实现（`src/renderer/src/App.tsx:369-400`）；`README.md:13` 的「schema v12 零迁移」与 `connection.ts:83-111` + `migrate.ts` 矛盾。**维护本仓库时不要把 README 当事实源。**
2. **审计明细表未回填**：`docs/parity-audit.md` 第 20–516 行记录了批次 0–4 与后续修复，但 `docs/audit/` 六份明细表仍是审计当时结论；权威复核结论在 `.aoci/.draft/audit/electron-diff.md`。
3. **`db/index.ts` 是全仓最长的 IPC 注册点**（431 行、117 个通道）：新增能力必须同时更新 `WRITE_DOMAINS`，否则「写操作不广播」这类 bug 不会报错、只会表现为界面不刷新。
4. **模块级单例 `POS_CACHE`**（`GraphPage.tsx:81`）：跨页面复用的同时，也意味着图谱坐标不随数据清理而失效——节点被删除后缓存条目仍在（内存占用极小，但需知情）。
5. **轮询而非推送**：浮窗 5s、提醒 30s、跨天 60s。三者都是渲染进程计时器，`关掉窗口/挂起进程` 会暂停维护逻辑。
6. **`schema.ts` 不可手改**：任何手改都会在下一次重新生成时被覆盖，并可能让 Python 版读不懂库。
7. **原生模块 ABI**：`better-sqlite3` 在开发环境与打包产物之间 ABI 不同，`dist` 之后必须跑 `postdist:*` 还原，否则开发模式启动即报错。
8. **文档真源排序**（建议）：`src/**` 代码 > `.aoci/.draft/audit/electron-diff.md` > `docs/windows-build.md` / `docs/optimization-proposals.md` > `docs/parity-audit.md` / `docs/audit/*` > `README.md`。
