### 任务与笔记的关联只留一张表

`task_note_ref` 并进了 `task_note_link`（迁移 v18）。

两张表的列几乎一样（都是 `task_id` + `note_id`），只是历史语义标签不同：图谱那边把前者叫「引用」、
后者叫「归属」。而按 `docs/specs/ownership-vs-reference.md` 的定义，**任务对笔记的关联本质都是引用** ——
分两张表的结果是同一对 (task, note) 可能各存一份，读的时候要用 UNION 去重（`listLinkedNotes` 就是这么绕过去的）。

现在写入统一走 `task_note_link`（带 `source` 字段记来源），读侧不再需要 UNION。
`task_note_ref` 表保留不删 —— 旧版本的导出文件里还有它，导入时要能落库。

### 笔记页的链接体检能修东西了

笔记树的「链接体检」菜单原本两项（孤儿笔记 / 失效链接），都只是**列出来看**。新增两项：

- **失效链接可逐个处理**：每条给「删掉这一行」的动作（改的是来源笔记的正文，所以先确认）
- **修复未绑定的链接**：这不是列表而是一个动作 —— 直接跑全库重链并提示修了几条。
  这类链接「标题能解析到、`dst_note_id` 却是空」，在 `brokenLinks` 里不算失效，
  但图谱的边与反链查询都按 id 走，不修就永远看不见它。

### 闪念转笔记时附件会跟着走

此前 `flashToNote` 只搬正文，附件留在 `attachments/pending/` 里成了孤儿 ——
注释写了迁移的意图，代码里没有实现。现在补上了。

顺带修掉一个会删用户数据的 bug：`pruneAttachments` 把 `pending/`（未归属附件的暂存区）
整个当孤儿删了。

### 知识成熟度：三个可点的数字，不做仪表盘

筛选条上多了「未被引用」一档 —— 有来源、却没人引用它，也就是「提炼了却没人用」。

设计结论见 `docs/specs/phase3-research.md` §2.3：这三个数（待确认 / 无来源 / 未被引用）的价值在于
**提醒你去处理**，而提醒要出现在你本来就待着的地方，不是一个要专门点进去的页面；
而且三十条笔记画分布图没有统计意义。

### 其它修复

- **重名笔记的链接会绑错**：改标题时只重绑了「旧标题掉链、新标题补链」，没处理同名的情况
- **失效链接的判据统一**：`brokenLinks()` 与 `outLinks()` 原先用了两套标准
- **`attach*` 前缀同时指附件与关联** → 关系类改用 `link*`，并合并了两份逐字相同的实现
- **i18n 骨架整套移除**（不需要多语言支持）
- **设置页分区重排**：通用 / 快捷键 / 任务与提醒 / 集成 / 数据与安全 / AI 整理 / 关于
