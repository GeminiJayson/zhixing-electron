### 修掉一个"点不到"的问题

任务项靠近窗口底部时，点它的**状态**或**标签**，弹出的菜单会从窗口下沿探出去 —— 最后几项（比如「已完成」「已放弃」）根本点不到。

排查下来是**五处弹层各写了一份定位代码，其中三处什么约束都没做**：

| 弹层 | 原先 | 现在 |
| --- | --- | --- |
| 状态菜单 | `top = 按钮底边 + 4`，无约束 | 下方放不下就翻到上方 |
| 优先级菜单 | 同上 | 同上 |
| 日期选择器 | 同上（日历更高，更容易被裁） | 同上 |
| 标签菜单 | 有夹取，但只有"硬塞进视口" | 翻转 + 夹取 |
| 通用弹出菜单 | 按项数**估算**高度（`48 + 项数 × 30`）再夹取 | 改用实测尺寸 |

估算那条尤其容易失手：菜单里有说明行、分组标题或长标签时，估算必然偏小，下沿照样会探出去。

现在这五种情况统一走一个函数（`lib/anchored-position.ts`），策略是：

1. 默认贴按钮下方、左对齐；
2. **下方放不下就翻到上方** —— 而不是硬夹进视口，夹进去会把菜单盖在按钮上，视线还得重新找；
3. 上方也放不下（按钮几乎撑满一屏）才退回夹取，至少保证内容可见；
4. 水平方向同理：右边放不下往左收，仍放不下再夹到安全边距。

尺寸一律取**实测值**，不估算 —— 菜单高度取决于项数、有没有说明行、有没有展开调色板，估算必然在某一项上出问题。

这类"漏一处就复现"的逻辑，本来就该只有一份实现。

### 验证

在真实运行环境里构造了触发场景：造 26 条任务、把最后一条滚到窗口底部（行底边 787px，窗口高 820px，下方只剩 33px），然后逐个打开弹层量位置：

| 弹层 | 结果 |
| --- | --- |
| 状态菜单 | 高 169px，翻到上方，完整可见 |
| 优先级菜单 | 高 297px，翻到上方，完整可见 |
| 标签菜单 | 高 105px，完整可见 |

日期选择器与其余入口共用同一个定位函数，未单独构造场景。

回归：两个 `tsc`、**453 项单元测试**、对比度门、控件高度门全绿。
