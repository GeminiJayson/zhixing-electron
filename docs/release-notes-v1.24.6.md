本地优先的个人待办 + 知识图谱桌面端（Windows x64）。数据只存在本机的一只 SQLite 文件里：无需注册账号，不联网也能完整使用。

### 修复：富文本 / Word 的编辑工具栏跟着编辑区一起缩放

1.24.5 的编辑区缩放（Ctrl / Cmd + 滚轮）把 `zoom` 挂在了正文区容器 `.sheet__body` 上 —— 而富文本与 Word 的格式条就在这个容器**里面**：它与正文是 `.rt-editor` 的两个兄弟子元素（`.tb.tb--panel` 与 `.rt-editor__body`），于是按住 Ctrl 滚滚轮，格式条连同里面的按钮一起被放大缩小。脚本编辑器的结果状态行是同一个毛病（实测 13px → 17px）。

现在改成按「内容容器」白名单缩，只缩正文那一层：`.md-editor` / `.rt-editor__body` / `.xlsx-ag` / `.link-table` / `.editor__preview` / `.scripted__edit`。六种格式逐一实测：

| 视图 | 正文 | 界面元素 |
| --- | --- | --- |
| 富文本 / Word | 缩到 150% ✓ | 格式条 29px、字号 12px **不变** ✓ |
| 脚本 | 代码区（含行号）缩到 130% ✓ | 状态行 **13px 不变** ✓ |
| Markdown | 缩到 80% ✓ | 工具栏本就在容器之外 |
| Excel | 缩到 120% ✓（AG Grid 内没有工具条） | — |
| 链接 | 缩到 90% ✓ | — |

脚本这一处顺带做了个取舍：缩的是代码区（`.scripted__edit`）而不是整个编辑器，这样行号与代码一起缩才对得齐。

### 新增：缩放比例按笔记各记一份

以前所有笔记共用一个比例，在一篇里调了，切到别的笔记也跟着变。现在**一篇笔记一份**：切到另一篇用它自己的，切回来恢复原来的。

存档是 `note.zoom.map`（`{ 笔记 id: 比例 }`），Ctrl + 0 只复位当前这一篇。实测：富文本调到 150% 后切到 Markdown 是 100%，Markdown 调到 80% 后切到 Excel 又是 100%，切回去各自恢复 150% 与 80%。

> **注意**：改动之后**之前那个全局比例不再生效**，每篇笔记从 100% 起步，需要的话各自调一次。
