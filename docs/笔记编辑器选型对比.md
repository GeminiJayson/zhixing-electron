# 笔记编辑器：第三方库选型对比

> 起因：需求「笔记类型为 Markdown / 富文本 / word / excel 的编辑与预览，引入成熟免费开源的第三方库实现」。
>
> 调查结论先说：**四种里已有三种在用成熟库**，真正需要换的只有**富文本**一种。

## 一、现状盘点（重要：三种其实已经是第三方库）

| 类型 | 现在用的库 | 许可 | 编辑 | 预览 |
| --- | --- | --- | --- | --- |
| Markdown | **CodeMirror 6** + **marked** | MIT | 有（CodeMirror） | 有（marked） |
| Word (.docx) | **mammoth** | BSD-2-Clause | **无** | 有（转成 HTML） |
| Excel (.xlsx) | **xlsx**（SheetJS 社区版） | Apache-2.0 | 自绘网格 | 自绘表格 |
| 富文本 | **无 —— 自研** | — | contentEditable + `document.execCommand` | 同左 |

两处值得注意：

1. **富文本是唯一没有第三方库的**，而且它依赖 `document.execCommand` —— 这个 API 已被标准**废弃**（deprecated），
   现在只有 Chromium 还在兼容。这是换库最强的理由，不只是「不够成熟」。
2. **富文本笔记存的就是 HTML**（`RichTextEditor` 的 props 是 `html: string`，直接写进 `innerHTML`）。
   这一条决定了迁移成本 —— **能原生读写 HTML 的库几乎零迁移**。

## 二、富文本库候选对比

数据取自 `npm view`（2026-09 实测）；体积是**解压后**大小，含类型声明与源码，**不等于打包进 bundle 的体积**（后者通常小一个数量级）。

| | **TipTap** | Lexical | Quill 2 | Slate |
| --- | --- | --- | --- | --- |
| 当前版本 | `@tiptap/react` 3.31.3 | 0.51.0 | 2.0.3 | 0.126.4 |
| 许可 | **MIT** | MIT | BSD-3-Clause | MIT |
| 内核 | ProseMirror | 自研 | 自研（Delta） | 自研 |
| 依赖数 | 3（react）/ 24（starter-kit） | 20（react） | 4 | 6 |
| 解压体积 | 553 + 53 KB | 3116 + 898 KB | 2965 KB | 2228 + 2740 KB |
| **文档模型** | **HTML（原生双向）** | JSON 树（需 import/export HTML） | Delta（需转换） | JSON 树 |
| 稳定度 | 3.x，已稳定 | 0.x，**尚未 1.0** | 2.x，最成熟 | 0.x |
| React 集成 | 官方 `@tiptap/react` | 官方 `@lexical/react` | 社区（react-quill 已停更） | 官方 |
| 扩展生态 | **最好**（表格/图片/协作等官方扩展齐全） | 中等 | 较多但偏旧 | 中等 |

### 为什么推荐 TipTap

1. **与本项目存储格式完全一致**。富文本存的就是 HTML，TipTap 的入参出参就是 HTML（`content` / `getHTML()`），
   已有的笔记**一条都不用迁移**。Lexical / Quill / Slate 都要经过一次模型转换，往返还会有损。
2. **MIT**，与本项目目前对第三方许可的谨慎一致（`THIRD-PARTY.md` 里登记得很细）。
3. **稳定**：3.x 已经是成熟版本；相比之下 Lexical 与 Slate 仍在 0.x。
4. **生态最好**：将来要加表格、图片、代码块、协作，官方扩展都有，不必再找野路子。

代价：它是 ProseMirror 系，依赖较多（starter-kit 带 24 个包），但都是同一家族的 MIT 包。

### 次选与排除理由

- **Lexical**（次选）：体积小、性能好，但**默认不是 HTML 模型**（是 JSON 树），与现有存储要额外转换；
  且仍在 0.x，API 变动相对频繁。
- **Quill 2**：最成熟稳定，但同样是自有 Delta 模型，且 React 集成依赖 `react-quill`（2022 年后基本停更）。
- **Slate**：灵活但**几乎所有东西都要自己写**，把「引入成熟库」变成了「自研第二遍」。
- **直接用 ProseMirror**：即 TipTap 的底座，省掉 TipTap 但换来大量手写代码，不划算。
- **Milkdown**：为 Markdown 设计，适合我们的 Markdown 笔记（但那边已经有 CodeMirror 了），不是富文本的最优解。

## 三、另外三种：建议维持现状，但有两件事要提前说清

### Markdown —— 已经是最优解，无需更换

`CodeMirror 6` 是当前 Markdown 编辑的成熟选择（MIT，活跃），`marked` 做预览（零依赖）。
如果希望预览与编辑**同源**（编辑区所见即预览），可以再评估 `@codemirror/lang-markdown` 的隐藏标记方案，
但那是体验优化，不是「缺库」。

### Word —— 预览可以升级，**编辑没有免费成熟方案**

| 能力 | 现状 | 可选升级 |
| --- | --- | --- |
| 预览 | mammoth 转 HTML（丢失排版） | **docx-preview**（Apache-2.0，1 个依赖，解压 952 KB）——更接近原样渲染 |
| 编辑 | 无（只能预览） | **没有**：开源界不存在成熟的 docx 所见即所得编辑器 |
| 导出 | 无 | `docx`（MIT）可以生成 .docx，但不是编辑 |

**这一条要请你确认预期**：如果「编辑 word」指的是像 Word 那样所见即所得地改 .docx，
那免费开源方案里做不到 —— 可行的是「**预览 .docx + 用富文本编辑器改内容 + 导出回 .docx**」，
排版会有损失。若你能接受这个折中，我按这个方向做。

### Excel —— 已有读写能力，**免费且成熟的可编辑表格库很少**

- `xlsx`（SheetJS 社区版）已能读写 .xlsx，现在的编辑界面是自绘网格。
- 想换成成熟的表格编辑器的话：`handsontable` **商用要授权**（不符合我们的许可口径）；
  `ag-grid` 社区版是 MIT 但定位是数据网格，不是电子表格；其余大多同样收费。
- **建议**：保留现在的自绘网格 + `xlsx` 做导入导出，把力气花在公式/格式这些实际需求上。

## 四、结论与建议

| 类型 | 建议 |
| --- | --- |
| 富文本 | **换成 TipTap**（`@tiptap/react` + `@tiptap/starter-kit`）—— 唯一真正需要做的替换，且零数据迁移 |
| Markdown | 保持 CodeMirror + marked |
| Word 预览 | 可加 `docx-preview`（如果想要更接近原样的排版） |
| Word 编辑 | 无免费成熟方案；折中方案见上，需你确认预期 |
| Excel | 保持 xlsx + 自绘网格 |

引入新依赖时会同步更新 `THIRD-PARTY.md`（本项目对第三方许可有登记习惯）。
