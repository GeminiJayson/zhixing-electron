# 领域文档

**单上下文（single-context）仓库**：一个 `CONTEXT.md` 加 `docs/adr/`，都放在仓库根目录。

## 两个文件的分工

| 文件 | 管什么 | 什么时候写 |
| --- | --- | --- |
| `CONTEXT.md` | **术语表**：这个词在本项目里指什么 | **按需创建**，出现歧义时补 |
| `docs/adr/NNNN-*.md` | **一个决定一份**：为什么选它、否掉了什么 | 做了**难逆转**的选择时 |

## `CONTEXT.md` 怎么写

**只写"容易理解错"的词**，不写通用词。每条形如：

```markdown
## 归属（ownership）

**任务或笔记"属于"某个容器** —— 文件夹、清单、分组。

与「引用」的区别是**排他性**：一个任务只有一个清单，但可以被多篇笔记引用。
分不清这两个词，就会把「移动任务到清单」和「关联任务到笔记」当成同一类操作。
```

**判据**：**如果这个词在别处也有、含义不同，就值得写。** 如果只是本项目内部一致、
外面没人会误解（比如"任务"本身），不用写。

## ADR 怎么写

**一页以内**，四段：**背景**（当时面对什么）、**决定**（选了什么）、
**否掉了什么**（以及为什么）、**代价**（接受了什么坏处）。

**最后一段最重要** —— 只写"选了什么"的 ADR 半年后会变成宣传稿；
写清"代价"的才让人知道什么时候该重新考虑。

## 创建时机

**别一次建全套。** 这两个文件是**用的时候才建** —— 硬凑一份术语表会写成同义词典，
而没人看的 ADR 不如写在提交信息里。
