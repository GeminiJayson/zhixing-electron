## 知行 ZhiXing 1.21.0

本地优先的个人待办 + 知识图谱桌面端（Windows x64）。数据只存在本机的一只 SQLite 文件里：无需注册账号，不联网也能完整使用。

### 密码保险箱：三项「写了但没验过」的补上

上一版发了保险箱，但有三项只有代码、没有实测 —— 这一版逐条收口：

- **剪贴板 30 秒自动清除**：判断「该不该清」的规则抽成纯函数（**只在剪贴板内容仍是当初写进去的那个值时才清** —— 否则会把你后来复制的东西一起抹掉），带 3 个用例；
- **无操作自动锁定**：判据同样抽成纯函数（支持「0 = 从不」、未解锁时不重复锁），带 6 个用例；
- **导入含不同主密码的库现在会明确报错**，而不是静默失败。实测发现导出侧本来就不含保险箱数据，所以正常文件不会触发；但手工拼的文件会 —— 而覆盖 `vault_meta`（盐）会让**原本能解开的库也进不去**，这道防御是必要的。

### 知识库：成熟度做成「可点的数字」

筛选条上多了「**未被引用**」一档 —— 有来源、却没人引用它，也就是「提炼了却没人用」。

**为什么不做成仪表盘**：这三个数（待确认 / 无来源 / 未被引用）的价值在于**提醒你去处理**，而提醒要出现在你本来就待着的地方；三十条笔记画分布图也没有统计意义。

另外，待确认的条目现在会**在笔记树里排到后面** —— 它们是「还没核实」的东西，不该占据视线最先落到的位置。

### 悬浮球消失过一次（已修）

把主进程的浮窗代码拆成独立模块时，**批量替换误伤了 IPC 通道名里的字符串** ——

```diff
- ipcMain.handle('widget:setBallShape', …)
+ ipcMain.handle('widget:widget.setBallShape', …)   // 渲染层调的还是旧名字
```

**类型检查查不出字符串内容**，所以编译、单测全过，但悬浮球渲染不出来。已修，并把这条写进维护约定：
**批量替换的边界要按「语法位置」想，不能只看字符。**

### 消除四处重复实现

审计时发现同一段逻辑存在多份独立实现。**今天它们逐字相同，但改一处忘另一处不会报错，只会静默失效。**

| 逻辑 | 原状 | 处理 |
| --- | --- | --- |
| 段落指纹（`sha1Hex` + `blockFingerprint`） | 渲染层与主进程**各一份**，且**两份注释都写着「这是唯一实现」** | 渲染层改为从 `@shared` 导入并再导出 |
| 读 CSS 时长令牌 `readTokenMs` | **四个页面各一份** | 合成 `lib/motion-tokens.ts` |
| `crc32` | `db/export.ts` 与 `db/preview.ts` 各一份（**两张表、两种写法**） | 合成 `shared/crc32.ts` |
| 缩略图 `makeThumb` / `readAsDataUrl` | 编辑器组件与 `lib/rich-media.ts` 各一份 | 组件改为导入；**顺带修掉一处行为差异**（组件那份出错会抛，lib 那份返回空串） |

**段落指纹那处最要紧**：它的注释写着「键必须与 `task_note_context` 表里的键逐字一致，才能互相定位」—— 两份实现意味着某天改了一处，**段落关联会「关联上了却跳不过去」，而且不报错**。

### 文档与代码的差异审计

这一版对文档做了一次完整审计（结论见 `docs/audit/doc-code-drift-2026-10-04.md`）：

- **`docs/01` 里 50 项功能状态标错了** —— 标着「未实现 / 部分实现」但代码里早就有的：FloatingDock、启动欢迎页、主↔浮窗联动、托盘随主题重建、富文本编辑器、种子数据、关窗前落盘、查找替换、番茄钟中断原因、命令面板命令集、段落级上下文、附件管理、文件夹增删改移、选文转任务、Markdown 批量导入、图谱增量通道、模板复制、一键自动布局……
- **真的没做的只剩两项**：代码签名与自动更新（都需要外部凭据或服务）；

- **新增 `docs/MAINTENANCE.md`**：文档地图 + 「改了什么 → 动哪份」的对照表；
- **新增 `CONTEXT.md`**：术语表（归属 vs 引用、清单/分组/文件夹同表、软删除、域广播……）。
