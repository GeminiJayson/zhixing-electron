# 笔记多标签页（tab）· 方案 v1

> **状态：已实施。** 方案原文保留不动 —— 它的价值在于「当时为什么这么判断」。
> 落地证据：`NotesPage.tsx` 的 `TABS_KEY` / `TAB_MAX` / `readStoredTabs`，
> 以及 `dropTab`（关闭一个 tab 后按「右邻 → 左邻 → 空态」决定激活谁）。

**目标读者：** 你（拍板的人）。
**读完应该能回答：** 树上单击算不算"新开一篇"、tab 条放哪、关掉最后一个 tab 会怎样、以及这次要不要动正文状态。

---

## 1. 要解决的问题

现在笔记页同一时刻只有一篇「当前笔记」（`selectedId` 一份）。想对照两篇笔记，只能来回点树 —— 每切一次就是一次完整的重新读库（`selectNote` → `flushPending` → 装载 effect），回去时滚动位置、展开的编辑形态全部回到初始态。

**"打开后留存"的真实含义**：把"我打开了哪几篇"变成一份**可见、可切换、可单独关闭**的列表，而不是一个瞬时的选中值。

---

## 2. 目标 / 非目标

**目标**

1. 打开过的笔记以 tab 留存，点 tab 即切换。
2. 每个 tab 可独立关闭（× 按钮 / 中键 / 右键菜单）。
3. 关闭当前 tab 后激活顺序符合预期（右邻 → 左邻 → 空态）。
4. tab 列表在切页（去「今日」再回来）与重启后能恢复。
5. 与既有形态不打架：笔记树收放、全屏编辑（zen）、窄窗覆盖式抽屉、未保存落盘。

**非目标（本期不做，写进来是为了划清边界）**

- 分屏 / 并排显示两篇（tabular 只切换，不平铺）。
- 每 tab 独立的滚动位置与光标位置记忆（切回来滚到顶部，见 §5 已知代价）。
- 拖拽排序、跨窗口拖出、tab 固定（pin）。
- 任务页 / 工作流页也上 tab（本次只做笔记页）。

## 3. 交互模型

### 3.1 打开语义（**最需要你拍板的一条**）

| 方案 | 树上单击一篇**未打开**的笔记 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A · 浏览器语义（推荐）** | 新开一个 tab | 与"留存"的直觉一致；行为可预测、好测 | 连点几篇就一排 tab |
| B · 编辑器预览语义 | 替换当前 tab（除非当前 tab 是"固定"的） | tab 不会失控 | 要教用户"双击才留存"，与现有习惯冲突 |
| C · 混合 | 新开，但超过上限时自动关掉最久未用的 | 兼顾 | 规则复杂，"我的 tab 为什么没了"难解释 |

**推荐 A**，配三道闸门把失控堵住：

- 已打开的笔记再点 → **激活已有 tab**，不重复开（这样树上反复点是安全的）。
- tab 上限 **12**，到顶时最后一位被挤出（并在 toast 里说明"已关闭最久未使用的标签"）。
- tab 右键菜单提供「关闭其他 / 关闭右侧 / 关闭全部」。

**统一规则（重要）**：所有"打开某篇笔记"的入口 —— 笔记树、`[[标题]]` 跳转、反链/出链列表、悬空链接一键新建、命令面板、从其他页面跳过来（`initialNoteId`）—— **一律走同一条**：已打开则激活，否则新开。语义只有一个，不用记特例。

### 3.2 关闭语义

| 动作 | 行为 |
| --- | --- |
| 点 × | 关闭该 tab；若它是当前 tab，激活**右邻**，无右邻则**左邻** |
| 中键点击 | 同 × |
| 关掉最后一个 | 回到现有空态（「从左侧选择一篇笔记，或点右上角新建」） |
| 关闭时正文还没落盘 | 先 `flushPending()`（复用现有机制），**不弹确认** —— 与现在切换笔记的行为一致 |
| 正在关闭的笔记被删除 | 自动关掉它的 tab（现有 `handleDelete` 里 `setSelectedId(null)` 的位置改为走关闭流程） |

### 3.3 tab 条的位置与形态

```
┌ 笔记 ─────── Markdown、Office 与链接笔记 ──────── [树收放] ┐  ← 页面头（现有）
├────────────┬──────────────────────────────────────────────┤
│            │ ▸ 会议纪要 ×│ 需求澄清 ×│ 2.0 收口方案 ×│   ← tab 条（新增，30px）
│  笔记树     ├──────────────────────────────────────────────┤
│            │ 标题行：标题 · 已保存 · 标签 · 归属            │  ← 现有「一张纸」
│            │ 工具栏                                          │
│            │ 正文                                            │
└────────────┴──────────────────────────────────────────────┘
```

- **位置**：编辑区（`.notes-main`）顶部，横跨编辑区宽度；`sticky` 吸顶。
- **高度**：30px，比工具栏（24px 按钮 + 边距 ≈ 32px）略矮，避免"tab 比工具还重"。
- **形态**：沿用现有胶囊语言（`--radius-pill`、`--bg-hover`、选中态 `--accent-soft`）。每个 tab = 格式图标 + 标题（截断，`max-width: 180px`）+ 关闭 ×（hover 才出现，避免一排 ×）。
- **未保存提示**：标题后加一个小圆点（`--accent-warm`），与标题行保存胶囊同色系。**不重复显示"已保存"**。
- **溢出**：横向滚动（`overflow-x: auto` + 隐藏滚动条），中键滚轮与触控板横滑均可。**装不下时右端固定出现一个「选择」入口**（`⌄ N`）：点开列出全部已打开的笔记、当前那枚带勾（复用 `PopMenu`）。
  - 2026-09-26 补：原方案写的是"不上下拉列出全部，12 个上限下没必要"，实测**8 枚就溢出**（编辑区约 700px）。横向滚动是个**不可见的手势** —— 被推出视口的那几篇等于没有入口，所以必须有这个看得见的兜底。判据是 `.note-tabs__list` 的 `scrollWidth > clientWidth + 1`，只在真溢出时出现。
- **单 tab 时是否隐藏**：见 §10 待拍板 —— 我倾向**隐藏**（≤1 个 tab 时不占那 30px，符合这个项目"不占位"的一贯取向），代价是"打开第二篇时 tab 条才出现"，有一点点跳。

### 3.4 与既有形态的关系

| 形态 | 行为 |
| --- | --- |
| **全屏编辑（zen）** | tab 条随页面头一起让位（zen 的语义是"只留正文"）；Esc 退出后 tab 条回来，列表不变 |
| **笔记树收起** | 与 tab 无关；树收起时 tab 条自然左移铺满编辑区 |
| **窄窗（编辑区 < 660px）** | tab 条保留，标题截断更短；信息条仍是覆盖式抽屉，二者互不影响 |
| **切换 tab 时的编辑形态** | `preview`（预览/编辑）与编辑区六件套按**当前 tab 所属笔记**重新判定；切回来时回到该笔记的默认态（不记忆上次是预览还是编辑）—— 若你希望每 tab 记住预览态，说一声，这是每 tab 状态分桶的第一块（见 §4） |
| **查找替换栏** | 打开着查找栏时切换 tab → 关闭查找栏（避免把 A 的查找词带进 B） |

## 4. 状态模型（技术核心，决定改动量）

现在笔记页有 **15+ 个"当前笔记"状态**（`current` / `title` / `content` / `dirty` / `officeEdit` / `excelRows` / `backlinks` / `outLinks` / `attachedTasks` / `linkDraft` / `blockDraft` / `propDraft` / `historyId` / `findText` …）。tab 化有两条路线：

### 路线 1 · 单一正文 + 切换时重载（**推荐**）

- 新增的只有两份数据：`openTabs: number[]`（打开顺序）与 `activeTabId`（复用 `selectedId`）。
- 切 tab 走**现有**的 `selectNote()`：`flushPending()` → 换 id → 装载 effect 重新读库。
- 正文状态仍然只有一份，"当前 tab"就是"当前笔记"，现有代码几乎不动。
- **代价**：切 tab 有一次读库（与现在切笔记完全同感）；Word/Excel tab 额外有一次文件解析（`.docx` → HTML、`.xlsx` → 单元格），重笔记上可感知。预览态、滚动位置不记忆。
- **收益**：改动集中在"多一个 id 列表 + 一条 tab 条"，风险低、回归面小；不会把 1832 行的 NotesPage 拆成一堆按 tab 分桶的状态。

### 路线 2 · 每 tab 一份草稿

- 把上面 15 个状态按 tab 分桶（`Map<noteId, NoteDraft>`），切 tab 零延迟、预览态与草稿都能记忆。
- **代价**：NotesPage 的状态层要重写，`persist` / 自动保存 / flushPending / Office 写回 / 各种菜单的 `selectedId` 语义全部要跟着改；内存里同时挂 N 篇的 HTML/单元格。
- 我判断这一版的收益（省一次读库）配不上这个改动量与回归面。

**推荐路线 1 落地，把路线 2 记为明确的下一步选项**（如果将来你要求"切 tab 不闪、记住预览态"，再单独立项）。

### 4.1 数据结构与持久化

```ts
// 组件内
const [openTabs, setOpenTabs] = useState<number[]>(() => readStoredTabs())  // 打开顺序
const [selectedId, setSelectedId] = useState<number | null>(null)          // 即 activeTabId

// localStorage（沿用现有偏好键风格）
// zhixing.noteTabs = { ids: number[], active: number | null }
```

- 写入时机：`openTabs` / `selectedId` 变化时（与 `zhixing.tree.notes` 同一套路）。
- 读取时机：组件挂载时。**过滤掉已不存在的 id**（笔记被删、库被换），并按 `notes` 列表刷新标题。
- 切页回来（`App.tsx` 里笔记页是条件渲染，切页即卸载）靠这份 localStorage 恢复 —— 这也是为什么必须持久化，而不是只放在内存里。
- 上限 12 落盘时同样生效（防止手工改坏 localStorage 后一次开几百个）。

## 5. 边界与不变量（施工时逐条对照）

1. **同名不同篇**：tab 按 `note.id` 去重，绝不按标题。
2. **`openTabs` 里不允许有不存在于 `notes` 的 id**：每次 `load()` 后做一次收敛（删除被删笔记的 tab）。
3. **`selectedId` 必须属于 `openTabs`**（空列表时 `selectedId = null`）：任何时刻这一条都要成立，否则会出现"高亮在树上、tab 条里没有"。
4. **树上高亮 = 当前 tab**：`NoteTree` 的 `selectedId` 继续吃同一个值，不新增第二份选中态。
5. **关闭当前 tab 后必须有新激活项**（列表非空时），不允许出现"有 tab 但都没选中"。
6. **切换前必落盘**：所有换 `selectedId` 的路径统一走 `selectNote()`（它已经 `flushPending`）；新增的 tab 激活/关闭路径也必须走同一条，不能直接 `setSelectedId`。
7. **从其他页面跳进来**（`initialNoteId`）：已打开则激活，未打开则**追加到末尾**并激活。
8. **新建笔记**：新建成功后新开 tab 并激活（现有 `handleCreateNote` 末尾已经是 `selectNote(created.id)`）。
9. **`[[标题]]` 悬空一键新建**：走 §3.1 的统一规则。
10. **删除当前笔记**：tab 关闭 + 激活右邻/左邻（而不是像现在直接清空到空态）。
11. **zen 下不渲染 tab 条**（不是 `display: none` —— 沿用本项目"收起即不渲染"的约定）。
12. **切换 tab 时关闭查找栏**，避免查找词跨笔记残留。

**已知代价（写清楚，别当 bug）**：滚动位置不记忆 —— 切回来滚到顶部。路线 1 的必然结果；要修就得上路线 2。

## 7. 验收矩阵（写成 `scripts/notetabcheck.mjs` 的断言）

| # | 断言 | 为什么守它 |
| --- | --- | --- |
| 1 | 树上连点两篇 → 出现 2 个 tab，第二个为激活态 | 基本盘 |
| 2 | 再点第一篇 → 仍是 2 个 tab，且第一篇变为激活态 | 去重与激活 |
| 3 | tab 标题 = 笔记标题；切换后编辑区标题/正文跟着换 | 切换真的生效 |
| 4 | 关闭**当前** tab → 激活右邻；关最右一个 → 激活左邻 | 激活顺序 |
| 5 | 关闭全部 → 出现空态提示，且 `openTabs` 为空 | 收尾 |
| 6 | 在 A 里输入（不等待自动保存）→ 立刻切到 B → 切回 A，内容还在 | `flushPending` 没被绕过 |
| 7 | 删除 A → A 的 tab 消失，自动激活右邻 | 与删除联动 |
| 8 | 切到「今日」再回「笔记」→ tab 列表与激活项恢复 | 持久化（也是这套架构的enabling条件） |
| 9 | zen 下 tab 条不在 DOM 里；Esc 后回来且列表不变 | 与全屏编辑的关系 |
| 10 | 打开 13 篇 → 只保留 12 个，最久未用的那个被关掉 | 上限闸门 |
| 11 | 中键点击 tab 关闭它 | 第二种关闭方式 |
| 12 | 已打开笔记被重命名 → 对应 tab 标题同步更新 | 标题不是快照 |
| 13 | 单 tab 时 tab 条不渲染（若采用 §10-B 的"隐藏"） | 高度取向 |
| 14 | 真实库零写入：脚本全程在副本库上跑 | 项目铁律 |

`notesheetcheck.mjs`（现有 48 项）**不扩**，避免把一个已经不小的脚本撑成两件事；但要在它的注释里加一句"tab 相关见 notetabcheck"。

## 9. 已知风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 切 tab 有加载感 | 路线 1 必然（Word/Excel 更明显） | 接受；要消除需上路线 2 |
| tab 爆炸 | 浏览器语义的固有代价 | 12 上限 + 去重激活 + 右键批量关闭 |
| 快捷键与 Electron 抢 | `Ctrl+W` 在 Electron 里常被当成"关窗"，`Ctrl+Tab` 也未必传得到渲染进程 | 首版只做鼠标交互；快捷键单独立项验证（见 §10-D） |
| localStorage 被改坏 | 手工编辑或旧版本残留 | 读取时过滤非法 id、截断到 12、`active` 不在列表内则取第一个 |
| 切页卸载 | `App.tsx` 条件渲染导致组件卸载 | 靠 localStorage 恢复（已在 §4.1） |

## 10. 已拍板（2026-09-26）

| # | 决策 | 结论 |
| --- | --- | --- |
| **A** | 树上单击未打开的笔记 | **新开 tab**（浏览器语义）；已打开则只激活不重复开；上限 12，到顶挤掉最久未使用的 |
| **B** | 只有 1 个 tab 时 | **隐藏 tab 条**（不占那 30px）；≥2 个时才渲染 |
| **C** | 持久化 | **跨切页与重启都恢复**（localStorage `zhixing.noteTabs`） |
| **D** | 快捷键 | **首版只做鼠标**：× 按钮 / 中键点击 / 右键菜单；`Ctrl+Tab`、`Ctrl+W` 留待单独立项（需先确认不与 Electron 关窗冲突） |
| **E** | 正文状态 | **路线 1**：单份正文，切 tab 复用 `selectNote()` 重载 |

据此本方案按 §8 的批次 1 开始实施；批次 2 的联动项（删除收敛、重命名同步、右键批量关闭、zen/窄窗、未保存圆点）随后收尾。
