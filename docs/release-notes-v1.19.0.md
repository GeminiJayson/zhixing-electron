### 玻璃拟态：从几个浮层扩展到整块界面

原先玻璃只给标题栏、弹窗和菜单用，面板、卡片、控件都是实色。现在改成**一层玻璃 + 各层半透明**：

| 层 | 用在哪 |
| --- | --- |
| **最透** | 窗口最外层、内容区背景 |
| **面板** | 标题栏 / 侧栏 / 主区 |
| **卡片** | 各类卡片（比所在面板实一档） |
| **控件** | 输入框 / 胶囊 / 幽灵按钮 |

**没有给每个控件挂背景模糊** —— 那会让合成层数量爆炸（每帧都要采样背后的整块区域），而视觉上并不需要：控件压在卡片上、卡片压在面板上，层层半透明叠出来就是玻璃的层次。真模糊只留给浮在内容之上的浮层：**弹窗、菜单、Toast、吸顶工具栏**。

### 三个参数可在设置里调节

**设置 → 外观 → 玻璃拟态**：

- **模糊半径** 0–40px（吸顶工具栏自动取其一半）
- **不透明度** 30–100% —— 同时决定窗口**透出桌面的程度**
- **饱和度** 100–250%

滑块下方有一块**彩色花纹的预览块**，三个参数拖一下就能看出差别。

> **为什么需要预览块**：主界面是浅灰白、几乎没有纹理，而模糊要有内容才看得见、饱和度要有颜色才起作用。直接看主界面拖滑块会觉得"没反应"。
>
> 同理，**模糊与饱和度只对浮层有效** —— 主界面各层的背后是纯色画布，糊一个纯色和没糊完全一样。这不是实现问题，是"背后有没有东西可采"的问题。设置页里写了这条说明。

### 窗口：透明、圆角与系统描边

主窗口现在是**真透明**窗口，能透出桌面，**窗口圆角由页面自己画**（无边框窗口在 Windows 上拿不到系统的 DWM 圆角）。

试过 Windows 11 的原生亚克力材质（能让桌面被模糊），但它由 DWM 绘制并**铺满整个窗口矩形** —— 四个角会露出材质本身，看着就是"矩形边框"。两者不可兼得：

| | 透桌面 | 桌面被模糊 | 窗口圆角 |
| --- | --- | --- | --- |
| OS 材质 | ✅ | ✅ | ❌ 直角 |
| **透明窗口（现用）** | ✅ | ❌ | ✅ |

另外补上了主窗口原先漏掉的两条：去掉 WS_THICKFRAME 描边与 DWM 系统投影。

### 修掉的两个 bug

**① 关掉玻璃后弹窗背景透明**

降级段里写的是「层令牌 = var(--bg-layer-solid)」，而那个变量本身就是「层令牌」的别名 —— **循环引用**。CSS 会把两个变量双双判为无效，于是所有引用它们的属性失效。改成一律直接取主题包的颜色。

**② 调整窗口大小 / 最大化还原 / 切换主题后玻璃失效**

Windows 上的透明窗口只要合成器被重建，逐像素透明就丢了。丢了之后窗口变成不透明矩形，页面里那些半透明叠在实底上，层次全没 —— 表现就是"玻璃失效 + 多出个矩形边框"。

排查依据：反复切换亮暗主题四轮之后，页面里所有 CSS 值都还是对的（不透明度变量与主区 alpha 与初始完全一致），但画面已经不对 —— 说明问题在窗口层，不在样式层。现在窗口几何一变化就重新确认一次透明。

### 验证

本轮回归全绿（只在临时库与隔离实例上跑，不碰真实数据）：

- 类型检查（主进程 + 渲染层）、**495 项单元测试**、对比度门、控件高度门
- 玻璃参数：模糊 / 不透明度 / 饱和度三项在预览块与弹窗上都实测跟随
- 关掉玻璃：主界面各处与弹窗均为不透明实色且保留圆角
- 截图对比（sha256）：**亮→暗→亮** 与初始一致、**最大化→还原** 与之前一致
- 对照实验：给主界面强行加上与弹窗相同的模糊，画面只变化 0.6% —— 印证了"主界面背后没有可采内容"

### 说明

**主窗口的玻璃观感不可能与弹窗完全一致。** 弹窗背后是遮罩与整个页面（文字、列表、卡片），模糊后能糊出层次；主界面各层的背后是彼此的同色底，模糊接近恒等变换。差别在层级，不在写法。
