### 挂载本地文件夹

知识库现在可以把**一个本机目录**挂到笔记树上，挂在**任意文件夹下**（挂载点就是笔记树上的一个普通文件夹：能改名、能排序、能拖走）。

- **文档不入库**：库里只留一条引用路径（`note_folder.mount_path`），内容每次从磁盘现读 ——
  外面增删文件，知识库跟着变，而知识库不需要搬家，也不会把几百个文件塞进 SQLite。
- 树里列出文件与子目录（按相对路径缩进），编辑区**只读预览**：文本给等宽排版、图片直接显示，
  超过 1MB 或不认识的格式只说明「用系统程序打开」。**改文件不走这里。**
- **自动感知**：`fs.watch({ recursive: true })` + 300ms 防抖，递归含子文件夹。
- **目录被删/移走时同步收掉挂载点**（watcher 回调里确认根目录还在，启动时再清一遍失效项）——
  否则树里会留一个永远点不开的空节点。
- 两道路径防线：拒绝 `..`、绝对路径、盘符、反斜杠；拼完之后再复核仍在挂载根之内。

### 跨域引用：挂载文件按正常笔记对待

挂载文件**被引用时懒建**一条轻量 note 行（`format='mount'`，只有标题与引用路径，**正文仍然不入库**），于是：

- 任务的「关联笔记」、工作流的同一套选择器里都能选到它（选中时才建行）；
- 正向引用（`[[文件名]]`）、反向链接、**图谱节点与连边**全部**零改动生效**（实测验证）。

设置 → 数据与安全 里新增「**失效的本地链接**」入口：卸载挂载点后那些行会保留并标记失效
（任务还关联着它们，直接删会让关联凭空消失），要清就来这里点一下。

### 任务关联知识库文件夹

任务可以关联**一个文件夹**，其下（**递归子文件夹**）的笔记会被**自动引用**：

- 外面新增/删除笔记，任务上的关联跟着建立/取消；
- **手动关联的那条永远不动**（用 `task_note_link.source` 区分 `manual` / `wiki` / `folder`，同步只动 `folder` 那一批）；
- 任务完成或放弃后冻结，不再跟着变。

### 完成任务时的总结

勾选完成任务时，若它关联了笔记，会依次问「**要不要总结**」→「**用 AI 还是自己写**」——
不选就是不总结（「直接完成」）。

- **手动**：一个富文本浮层，复用快速笔记那套 tiptap（同一份扩展、同一条工具栏）。
- **AI**：按预算截断（每篇 1200 字、总量 24000 字），挂载文件现读磁盘，**读不到的如实标注**，不让模型对着空内容编。
- **总结落库知识库**：新建一篇「`总结 · <任务名>（日期）`」的笔记并关联回任务 ——
  塞进任务备注的话它搜不到、引用不了、图谱里也看不见，而总结恰恰是最该被再次读到的内容。
- 随时可以「跳过，直接完成」。

### 修复

- **图谱连线规则审计**（一次系统性检查，四个问题）：
  渲染层自己又实现了一套落库分派 —— 主进程补了 `folder|folder` 之后画布上仍然连不上（页面那份落到 else 直接弹「暂不支持」）；
  `canEditEdge` 禁止删除文件夹↔文件夹的边（注释里那句「主进程也不支持」早已过时）；
  连线没有拦「连到自己」；
  **环路校验的参数顺序反了** —— 「把文件夹上移一级」（挂到祖先下，最常见的操作）被误判成环而拒绝，
  而「挂到自己的子孙下」只是**碰巧**判对。
- **收件箱页不实时刷新**：`/clip` 走的是 HTTP 端点、不经过 IPC 的写域表，落库后没有广播；
  而收件箱页本身也没订阅任何域。两处都补上了。
- **数据库视图打开后没替换笔记区**：`.notes-wrap.is-hidden` 与整段 `.notetable*` 的样式在一次整理里被连带删掉
  （类名还挂在 JSX 上），于是打开后笔记树与编辑区照样显示、表格被挤成一条。
- **图谱「全部文件夹」与笔记树「移动到…」的层级**：改为按**树序**铺平（父后紧跟子 + 实际层级），
  并排除「自己与自己的子孙」（挂到子孙下必成环，列出来只会让人白点一下）。
- **工具栏「模板」菜单**：主行为改为**插入到当前笔记**（原先是点一下就新建一篇，当前这篇纹丝不动）；
  「用模板新建一篇」保留为第二组。
- **笔记编辑区标题行**：胶囊与运行环境下拉统一到 20px 一档（方向是把控件压下来，而不是把胶囊拉高）。
- **`db.notes()` 的列投影缺字段**：两处硬编码的 SELECT 少了 `props` / `script_runtime` / `mount_ref` ——
  也就是说**脚本笔记的运行环境与笔记属性在渲染层一直读不到**。
- **对话框遮罩吞掉「确定」**：遮罩监听 `mousedown` 且不判断目标，按钮的 mousedown 冒泡上去先按「取消」结算，
  随后按钮的 click 已无人接收 —— **真实鼠标点「确定」会被当成「取消」**，影响所有确认框。
- **写总结的浮层不出现**：监听器挂在了一个已卸载的组件实例上，它调用的 setState 被 React 静默忽略
  （诊断值：setJob 记到了任务 id，而渲染读到的 job 始终是 null，控制台无任何报错）。改成由 App 持有状态。
