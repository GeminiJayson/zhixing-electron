### 新增：清空数据库

设置 → 数据与安全 → 最后一行「**清空数据库**」：删掉全部笔记 / 任务 / 闪念 / 工作流等业务数据，回到刚装好的状态。

三处刻意的设计：

- **先自动备份**：这是不可逆操作，而应用本来就每次启动备份（保留最近 10 份）—— 这里顺手先备一份，
  点错了还能从「自动备份」里恢复；
- **跳过 FTS 影子表**：`note_fts` / `task_fts` 本身是虚表，清空没问题；但它们的影子表
  （`*_fts_data` / `_idx` / `_docsize` / `_config`）由 SQLite 自己维护，手动删会让全文索引坏掉 ——
  之后搜索要么报错、要么悄悄查不到；
- **保留 settings 表**：那里是主题 / 热键 / AI 配置，不是用户数据，清掉等于顺带把所有设置重置回默认。

界面要求**原样输入「清空」两个字**才执行（一个「确定」按钮太容易误点，而它删的是全部笔记）。

### 挂载的本地文件夹：层级与样式和笔记树完全一致

之前挂载点下面是「平铺 + 按相对路径缩进」：看着像树，但子文件夹**不能折叠**，而且用的是另造的一套类名
（`.ntree__mount` / `.ntree__mount-size`），跟旁边的笔记文件夹一眼就不一样。

现在：

- **目录行 = `.ntree__folder`**（带折叠箭头，折叠状态与真实文件夹**共用同一份**记录）；
- **文件行 = `.ntree__note`**（图标 + 标题，与笔记行同构）；
- 缩进照笔记树的约定（文件夹 6 + depth×14、笔记 10 + depth×14），并带上路径虚线要用的 `--tree-depth`；
- 层级与本地目录**逐一对应**（实测：目录 d1 → 子目录 d2 → 子子目录 d3 → 文件 d4）；
- 顺手修了挂载点自己的子项计数（它数的是「真实笔记数」，对挂载点恒为 0）。

### 修复：知识库的树不跟着数据变

`note` 域的订阅**挂在「当前选中的笔记」上**（没打开笔记时压根不订阅），回调里也**只刷反链 / 关联任务 / 标签**
—— 从来没有重拉过笔记与文件夹。同一个 bug 有三个症状：

1. **卸载 / 挂载本地文件夹后，树里的那个节点不动**（要切页才更新，用户反馈的就是这个）；
2. **别的页面新建 / 删除笔记，知识库的树不跟着变**；
3. **重命名文件夹后，树里还是旧名字**。

改成恒常订阅 `note` 域 → 重拉整棵树；当前笔记自己的反链那套保留为独立的第二个订阅。
实测：挂载后 2.5 秒内节点出现（连它下面已展开的子目录一并渲染），卸载后 2.5 秒内消失，全程不切页不刷新。

### 修复：回收站「清空此分类」把三类都清了

按钮写的是「清空此分类」，代码调的却是 `emptyAllTrash()` —— 而按钮的禁用条件又**只按当前分类有没有条目**判断：
用户在「笔记」分类下看到按钮可用，点下去连任务和闪念一起没了。

现在真的只清当前分类，确认框也写清是哪个分类、多少条：
「清空「笔记」分类的 30 条记录？无法恢复。」
