### 工作流的步骤，现在看得见也管得住

这一版把工作流的**执行**做实了：步骤跑起来之后有什么输出、算不算成功、什么时候自己跑、能不能套别的流程。

**关键字判定 —— 不再只看退出码**

命令和脚本的退出码并不总能说明问题：有的工具失败也返回 0、有的把结论写在日志里（`BUILD SUCCESS` / `ERROR`）、有的跑一半停下来问 `(y/n)`。现在节点的编辑弹窗里多了一栏「日志判定」：

- **判定口径**：只看退出码（默认，与从前完全一致）/ 日志优先、没命中再看退出码 / 只看日志、没命中就算失败
- **关键字规则**：一行一条，包含或正则，命中后算成功、算失败、还是"等待输入"。规则**从上到下**匹配，先命中的说了算 —— 把 `ERROR` 排在 `SUCCESS` 前面，就表示两个都出现时按失败算
- **自动输入**：命中「等待输入」时把预设回答写进 stdin（回答里写 `\n` 会被还原成真换行）

执行过程是**流式**的：长命令能边跑边看，不必等它结束。

**子流程 —— 把另一个流程当成一步**

步骤的动作类型多了「子流程」，选一个模板整体接进来。它跑完之后，**结果与它的日志会回到父流程的那一步**，条件节点可以接着用「上一步日志」按关键字判定 —— 于是"子流程日志里出现 X 才走父的这一支"是同一条链路。

子流程失败或被中止时，父流程**停在那一步等人处理**，不会自动往下走。

**什么时候自己跑起来**

模板上可以配三种入口：

- **定时**：每 N 分钟 / 每天固定时刻。应用没运行时不会触发，错过的时间也不补
- **任务状态**：某个任务变成某个状态就启动本流程
- **外部调用**：生成一个令牌，用 `POST http://127.0.0.1:<端口>/hook/<令牌>` 触发它（脚本、CI、手机快捷指令都能用）

外部调用端点只监听本机回环、端口由系统分配、只接受 POST。

### 执行记录改成独立弹窗

实例的 🕘 按钮打开「执行记录」：**按步骤分组**的时间轴 —— 每一步什么时候跑的、结果如何、现在停在哪；点开某一步就能看到**它的完整日志**（命令/脚本的输出 + 进入 / 完成 / 关键字命中等过程记录）。

节点名按**该实例自己的模板**解析，所以即使你正开着另一个流程，记录里的步骤名也不会串。
