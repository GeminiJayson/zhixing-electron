### 浏览器扩展：图片下载成本地文件，不再留外链

剪藏正文里的图片现在会**逐张下载**到 `<数据目录>/attachments/clip/<每篇一个目录>/`，
正文引用改写成 `zx-attach://`，由主进程注册的同名协议读文件（渲染层零改动，`<img>` 直接显示）。

为什么不留外链：原站删图、换 CDN、上防盗链每天都在发生 —— 留一个 `https://` 地址等于赌对方不删，
而剪藏的价值就是"以后还能看"。

几个刻意的取舍：
- **单张失败只跳过那一张**（保留它的外链），不连累整篇剪藏；
- **content-type 不是 `image/*` 的一律不存** —— 防盗链常把图片请求 302 到登录页，存下来就是一张伪装成图的网页文件；
- 超过 5MB、或一篇超过 20 张就不抓（图集页会把落库拖住）；
- 协议只读附件目录，路径合法性两层挡（拒绝 `..`、斜杠、多级路径 + 前缀复核）。

同时处理了抓图的两个常见坑：**相对地址**（`/uploads/a.png` 存进库里就是死链）与**懒加载**
（真图在 `data-src`、`src` 只是 1×1 占位），`srcset` 的每一段也一并绝对化。
插件侧与主进程侧各做一次 —— 主进程那层是兜底，旧版扩展与 curl 手测都用得上。

### 图片抓取不会拖住正文

`/clip` 现在**先用原始外链正文落库、立刻返回**，图片下载放在响应之后的收尾里做（下完再改写那一条）。

这一条是刻意的时序设计：图片是网络操作，一张最坏 10 秒、一篇最多 20 张 —— 同步等它意味着
插件点完剪藏要转几分钟圈，任何一张卡住都会拖住正文。实测：3 张各 3 秒的图，剪藏响应 **4 ms**
（同步等待会超过 9000ms），8 秒后正文里的引用变成 `zx-attach://`。

任何图片问题（断网、防盗链、那条闪念已被删）都不会影响已经落库的正文。

### 浏览器扩展：跟随安装包分发

此前扩展只躺在源码仓库里 —— 装安装版的用户根本拿不到。现在它随包分发
（`electron-builder.yml` 的 `extraResources`），设置 → 集成 → 浏览器扩展里显示目录并给「打开目录」按钮，
照着在浏览器里「加载已解压的扩展程序」即可。

### 浏览器扩展：滚动到底部的内容不再丢

全文剪藏**先自动滚动一遍**再抓 —— 没滚到的内容根本不在 DOM 里，Readability 再聪明也读不到。
只在全文剪藏时做（区域剪藏是用户自己看着选的，页面乱跳会让他选错），有 4 秒 / 60 步上限，
结束后**还原原来的滚动位置**。

### 修复：删掉剪藏后再剪同一页报「已存在」

查重 SQL 漏了 `deleted_at IS NULL` —— 删除是**软删**（只写 `deleted_at`，行还在表里），
于是删掉一条剪藏、再剪同一页仍被判成重复，什么都进不来。整页（按 URL）与选区（按内容指纹）两条都已修。

### AI 整理：API Key 的发送方式可配

默认已经按协议走（OpenAI 兼容 → `Authorization: Bearer`；Anthropic → `x-api-key`；Gemini → 查询参数），
这一版补上两个真实会遇到的缺口：

- **Key 自带 `Bearer ` 前缀**时会拼成 `Bearer Bearer sk-…`（服务端只当你给了一个非法 token，
  报 401 却看不出原因）→ 现在先归一化；
- **中转服务把 Anthropic / Gemini 的请求形状配上 Bearer 鉴权** → 设置 → AI 整理里新增「鉴权方式」：
  自动（按协议）/ `Authorization: Bearer` / `x-api-key` / 查询参数。选「自动」时行为与以前完全一致。
